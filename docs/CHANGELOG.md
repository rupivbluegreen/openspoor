# Changelog

All notable changes. Dates are UTC.

## Unreleased
- M0: Go single binary (api/worker/all/migrate/bootstrap/seed), PostgreSQL RLS tenancy, hash-chained audit log, job queue, event bus (Redpanda mirror), Docker Compose (Postgres, Redpanda, Keycloak, Temporal, SeaweedFS), CI (build, vet, race tests on Postgres 16, golangci-lint, go-arch-lint, OpenAPI diff, frontend typecheck/test/build), ADR-001…006.
- M1: organizations, sites (GLN), licenses, users and roles, API keys, audit log + chain verification, e-signatures with re-authentication, alerts inbox; products with CSV import and packaging hierarchy per market.
- M2: serial pools (FF1 random or sequential), idempotent allocation, commissioned bitmaps, pool-low alerts, GS1 element string / Digital Link / DataMatrix encode and decode.
- M3: EPCIS 2.0 capture (JSON-LD, XML 2.0 and 1.2), CBV and master-data validation with per-event errors, idempotent re-capture, query interface with pagination, named queries, HMAC-signed webhook subscriptions, serial state and aggregation projections, serial history and tree.
- M4: DSCSA TI/TS generation per shipment, outbound over HTTPS (AS2 through an interface, ADR-007), inbound reconciliation against the ASN, VRS responder and requester with a lookup directory; partner directory, invitations and connections.
- M5: connector SDK (separate Go module, `github.com/openspoor/connectors-sdk`) with a contract-test harness; EU FMD (EMVS) and Saudi RSD connectors against bundled mock hubs; parsed rejection reasons in the regulatory alert inbox with one-click resubmit; versioned YAML rule packs (EU FMD, US DSCSA, SA RSD, US FSMA 204, EU EUDR).
- M6: EDI mappers (X12 856/850, EDIFACT DESADV/ORDERS, IDoc) and B2B documents; supplier compliance certificates.
- M7: Helm chart; backup and restore runbook; GAMP 5 validation pack (URS, risk assessment, IQ template, OQ report generated from tests and traced to the URS); OpenAPI 3.1 generated from the router, with a staleness test; k6 load tests; OWASP ZAP baseline (0 High, Medium or Low findings); CSP and HSTS headers; the binary serves the console, verify and operator apps; migrate-on-start for compose.
- M8: SaaS mode with host-based tenant routing, self-service signup and plans, per-tenant branding, OpenFeature flags (Unleash provider), Lago usage metering, GDPR export, and tenant deletion by crypto-shredding the per-tenant data key.
- M9: food: lots, CTEs and KDEs, transformations, FSMA 204 sortable spreadsheet, EUDR plots and due-diligence statements, recalls, cold-chain sensor readings and excursions. Federation: did:web node identity, Ed25519-signed envelopes, replay protection (ADR-008).
- M10: governed agents with scoped tools, approval gates and reversible actions; control tower; case management; workflow designer; assistant over tenant data (Claude via the official Go SDK, with refusals handled).
- M11: app marketplace with sandboxed developer apps; learn articles; peer benchmarks with k-anonymity (k = 5); UDI device registration (GUDID and EUDAMED payloads prepared locally).
- Migration tooling: CSV and EPCIS imports from incumbent systems; shadow runs that compare final serial states.
- Performance: a 100,000-event EPCIS document is captured atomically in 6.1 s (≈16.4k events/s) on 4 vCPU. Hot queries carry an explicit tenant predicate, because the RLS `OR` operator-bypass prevented index use under generic plans. Bulk capture stages through COPY into a temporary table, since PostgreSQL forbids COPY into RLS tables.
- Frontend: console, operator and verify apps (React 19, Ant Design 6, pro-components) in English, Dutch and Arabic (RTL); EPCIS playground.
- Site: GitHub Pages site with the measured benchmarks.
- Decisions (2026-10-23): capture stays acknowledged on the PostgreSQL commit (ADR-009 accepted); Viewer is strictly read-only, including forms and workflows; audit entries are pseudonymised at write time (user ids as actors, keyed hashes for e-mail, phone and person names, per-tenant key); the assistant keeps the hosted model and the local-model option.
- Security hardening: federation mutual TLS (peer certificate pinning on delivery, pinned client certificate required on the inbox, TLS 1.3 minimum); optional HTTPS and HTTP-to-HTTPS redirect from the process; secret settings from files or HashiCorp Vault-compatible KV v2 (`secretsrc`); throttled, uniform password logins with `auth.login_failures` alerts (`login_attempt`, migration 00021); password deny-list and local-part rule; `govulncheck` and `pnpm audit` in CI; ASVS 4.0.3 level 2 self-assessment and a threat-model note.
- B2B transaction registry and KPI library: `pkg/edi` Types registry with 60 standard-backed transaction types (X12 sets, EDIFACT messages, required fields, status codes, validation rules), generic template-driven X12 and common-subset EDIFACT writers and readers, `GET /b2b/types`, mapping-studio targets from the registry type; 36 formula-defined KPIs with daily series, per-tenant goals and peer benchmarks (`GET /kpis`, migration `00022_kpi.sql`); console page "KPI library".
- AS2 transport (ADR-007 amended): in-process AS2 sender and receiver (`pkg/as2`, CMS by `github.com/smallstep/pkcs7`) with S/MIME signing and optional encryption, sync and async signed MDN receipts, Message-ID idempotency, pinned partner certificates stored per connection and sealed with the tenant key (`PUT /partners/{id}/as2`), the node's AS2 station (`/as2/station`), the public `/as2/receive` endpoint, audit entries and `as2_message` rows in the message log (`kind=as2`); migration `00023_as2.sql`. Algorithm profile, trust model and payload shape are `TODO(spec)` in `docs/OPEN_QUESTIONS.md`.
- SSRF guard and API rate limits: `internal/core/egress` (one dial-time guard for webhooks, connectors, DSCSA HTTPS, AS2 and partner probes; `OPENSPOOR_EGRESS_ALLOW_PRIVATE`, `OPENSPOOR_EGRESS_ALLOW_CIDRS`; metadata addresses always refused unless named); `internal/core/ratelimit` (per-tenant and per-API-key token buckets by plan, 429 with Retry-After, operator exemption, `OPENSPOOR_RATE_LIMIT`, `OPENSPOOR_RATE_LIMITS`, metrics); CI coverage gate (80 % per domain package) and CycloneDX SBOMs; tag-triggered release workflow with keyless image signing. Federation delivery and the regulatory-source watcher still need to adopt the guard.
- Message log: failed outbound TI/TS rows are retryable (`POST /messages/{id}/retry` re-sends through the dscsa outbound path, audited, one retry at a time); delivery attempts are counted.
- FSMA 204 export: columns unchanged; the FDA template could not be verified from the repository, so the open points are listed in `docs/OPEN_QUESTIONS.md`.
- Account security (ASVS V2/V3): password change with the current password; password recovery by an e-mailed, single-use, 30-minute token (uniform answers, throttled with the login guard); TOTP second factor (RFC 6238) with enrol, confirm, disable, hashed recovery codes, enforcement at sign-in and a tenant policy that requires it for administrators (sessions limited to enrolment until done); an administrator can reset a user's second factor; per-user token version so password and second-factor changes, role or status changes and `POST /auth/logout` revoke tokens; the cookie credential was removed (no CSRF surface) and tested; `Cache-Control: no-store` on authenticated and sign-in responses; webhook secrets sealed with the tenant data key; `openspoor rotate-keys` re-seals tenant data keys and the node key under a new master key; public rate limiters use the proxy-aware client address (`httpx.ClientIP`, `platform.ClientIP` delegates). Migration `00024_account_security.sql`. Console: Settings > Security (password, second factor, tenant policy), a verification-code step at sign-in, a recovery page, sign-out revokes the session.
