# OWASP ZAP baseline scan

Passive (baseline) scan of the API, run before each release.

| | |
|---|---|
| Date | 2026-10-22 |
| Tool | OWASP ZAP 2.16.1, automation framework (`-cmd -autorun`) |
| Target | `openspoor all` with the demo seed, authenticated as a tenant admin |
| Coverage | every operation in `/api/v1/openapi.yaml` imported (210 URLs) plus spider |
| Result | **0 High, 0 Medium, 0 Low**; 1 informational ("Authentication Request Identified" on `/api/v1/auth/login`, expected) |
| Server errors | none: no 5xx response to any generated request (149 × 2xx, the rest 4xx validation and authorisation refusals) |

Headers set on every response (`internal/app/app.go`): `Content-Security-Policy` (scripts same-origin only; inline styles allowed for
Ant Design's runtime CSS), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`, and
`Strict-Transport-Security` when the request arrived over TLS. No server banner.

## Reproduce

```sh
eval "$(scripts/testdb.sh | grep '^export')"
# start the server against a throwaway database (see scripts/loadtest.sh), then:
java -jar zap-2.16.1.jar -cmd -autorun docs/security/zap-plan.yaml
```

`docs/security/zap-plan.yaml` is the plan used; set `TOKEN` to a bearer token for the replacer rule.

Not covered: an active scan (fuzzing and injection), which belongs in a staging run. The XML capture body is not generated by ZAP; it is covered by the EPCIS
codec tests and the `invalid-events` fixtures.
